## Scope of this experiment

- Read-only CPUID/CR0/CR4/EFER probing verifies NX capability, IA-32e
  4-level paging, PAE and no PCIDE/LA57; the gate **reports** whether
  CR0.WP and EFER.NXE are enabled, but makes **no control-register or MSR writes**.
  Both must be enabled and rechecked before any future CR3 cut.
- A separate, noinline EFI code **anchor** provides one symbol address.
  The current firmware page-table walk checks the first/last bytes of the
  anchor's page are in the same physical page, both executable (effective
  NX clear), and the complete physical page falls into a valid
  `EfiLoaderCode` firmware descriptor. The private page table maps that
  page at the **same linear virtual page** with supervisor-only RX rights.
  A RW alias of an existing RX frame is rejected.
- This anchor **is not** a real CR3-switch trampoline and does not prove
  a full assembly function's byte range, live RIP, ABI stack, GDT/IDT/TSS,
  or instructions after ExitBootServices. It only proves a constrained
  page mapping on the pinned QEMU/OVMF profile.
- The initial physical/linear old-CR3 root read still relies on a QEMU-only
  unverified bootstrap assumption; it remains an explicit P0 blocker.
  A hardware reset/fault is not proof of safe mapping.
- Distinct E2d-only `isa-debug-exit` port write `0x25` produces
  observed host code **75**. The full kernel clean-success code 65 stays disabled.

## Hard boundaries / next engineering gate

Neither source nor CI writes CR3, attempts ExitBootServices, installs a
GDT/IDT/TSS, enables exception stubs, or calls the linked high-half kernel.
Before that phase:
1. independently bound and inspect the complete executable bridge
   instruction span and its RIP/stack/descriptors old/new linear translations;
2. provide emergency exception handlers, validated GDT/IDT/TSS and #DF IST;
3. check CR0.WP + EFER.NXE at cut, no forbidden aliases or mapped guards;
4. create immutable BootContext and validate exact current UEFI map key;
5. implement at most two ExitBootServices calls and no forbidden post-success
   firmware service calls;
6. run real QEMU protected kernel entry and negative probes, with independent
   host exit 65 only for genuine protected success.
